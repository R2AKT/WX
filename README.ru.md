## Аппаратная часть

### Мастер (WX_MASTER)

| Компонент | Интерфейс | Назначение |
|-----------|-----------|------------|
| Arduino Nano (ATmega328P) | — | Главный контроллер |
| ENC28J60 | SPI | Ethernet (пассивный PoE) |
| DS18B20 | 1-Wire | Температура воздуха (°C) |
| BME280 | I2C (0x76) | Температура, влажность, давление |
| SHT31 | I2C (0x44) | Температура, влажность (избыточность) |
| AS5600 | I2C | Направление ветра (магнитный, 14 бит) |
| TLE4934 | GPIO (интеррапт) | Скорость ветра (Hall, 360 имп./об) |

### Слэйв (WX_SLAVE)

| Компонент | Назначение |
|-----------|------------|
| Arduino Nano + ENC28J60 | Приём UDP |
| 16×2 LCD (I2C, PCF8574) | Локальный дисплей |

### Python-хост

- Raspberry Pi (или любой Linux-хост в сети)
- Запускает: `Gen_WX   .py`, `WX_2_MQTT   .py`, `WX_2_WEE   .py`
- WeeWX 5.2.0 (опционально)

## UDP-протокол (36 байт, бинарный)

Broadcast на `255.255.255.255:4001`, 1 Гц.

| Смещение | Размер | Тип | Поле |
|----------|--------|-----|------|
| 0–5 | 6 | bytes | MAC-адрес |
| 6–9 | 4 | float32 LE | DS18B20 Температура (°C) |
| 10–13 | 4 | float32 LE | BME280 Температура (°C) |
| 14–17 | 4 | float32 LE | BME280 Относ. влажность (%) |
| 18–21 | 4 | float32 LE | BME280 Давление (мм рт.ст.) |
| 22–25 | 4 | float32 LE | SHT31 Температура (°C) |
| 26–29 | 4 | float32 LE | SHT31 Относ. влажность (%) |
| 30–31 | 2 | int16 LE | Направление ветра (0–360°) |
| 32–35 | 4 | float32 LE | Скорость ветра (м/с) |

### Кодирование ошибок (NaN → sentinel)

| Датчик | Значение ошибки |
|--------|-----------------|
| Температура (любая) | −127.0 °C |
| Влажность (любая) | 100.0 % → clamp 99 |
| Давление | 100.0 мм рт.ст. |
| Ветер | 0 |

### Допустимые диапазоны (валидация на стороне приёмника)

| Поле | Мин | Макс |
|------|-----|------|
| Температура | −50 °C | +50 °C |
| Давление | 700 мм рт.ст. | 800 мм рт.ст. |
| Влажность | 0 % | 99 % |
| Направление ветра | 0° | 360° |

### Замечания по рефакторингу

Исходные скрипты рефакторизованы для исправления:
- `udp_socket.close()` — несуществующая переменная → единообразное именование
- `math.isnan()` на `int` → только для float-полей
- `DataReady = True` (DEBUG-переопределение) → корректный 60-секундный цикл
- `mqtt_client.loop_stop()` ДО главного цикла → перенесено после
- WeeWX: `rapid_wind` вложенный `[[...]]` → плоский `[...]` (v1.7.1)
- WeeWX: конфликт `bind()` порта 4002 → только `sendto()`
- Arduino: отсутствует `ether.packetLoop()` в UDP-режиме (DHCP истекал)
- Arduino: SHT NaN → 0 (валидное значение!) → sentinel −127/100
- Arduino: `sizeof(int)` непереносимо → явная работа с байтами
- Slave: парсил 28-байтовый протокол вместо 36-байтового

## Интеграция с WeeWX (Tempest Protocol v1.7.1)

`WX_2_WEE   .py` отправляет WeatherFlow Tempest UDP JSON на `127.0.0.1:4002`.

| Тип сообщения | Интервал | Формат |
|---------------|----------|--------|
| `rapid_wind` | 1 Гц (каждый пакет) | `ob: [ts, speed_m/s, dir_deg]` (плоский) |
| `obs_st` | 60 с | 18 полей, `obs: [[...]]` |
| `obs_air` | 60 с | 8 полей, `obs: [[...]]` |

**Ключевые настройки `weewx.conf`:**

```ini
[DataSources]
    driver = user.WeatherFlowUDP
    UDPBindAddress = "127.0.0.1"
    UDPBindPort = 4002

[StdFrame]
    archive_interval = 60
```

Данные ветра: `rapid_wind` (live) → маппинг WeeWX `windSpeed`/`windDir`.

## APRS-вывод

`Gen_WX   .py` записывает файлы в `/tmp/` (цикл 60 сек):

| Файл | Формат |
|------|--------|
| `WX.txt` | APRS mic-E |
| `WX_hum.txt` | Человекочитаемый |
| `WX_hyb.txt` | Гибридный (APRS + текст) |

**Пример (APRS):**
```
!5556.34N/03758.45E_c180s007g012t037r...p...P...h54b10066Shchyolkovo WX station
```

**Пример (человекочитаемый):**
```
:=5556.34N/03758.45E_Щёлково МС: Температура => 2.5 C; Ветер => 3.2 м/с, Ю; Порыв => 7.8 м/с; Влажность => 54 %; Давление => 741 мм рт.ст.
```

## Трекер ветра

Скользящая статистика (`WindTracker` в `wx_common.py`):

| Период | Буфер | Метод |
|--------|-------|-------|
| 1 мин | 60 образцов | Сумма / 60 (включая нули в первую минуту) |
| 10 мин | 10 × 1-мин | Сумма 1-мин средних / 10 |
| 1 час | 6 × 10-мин | Сумма 10-мин средних / 6 |

Также отслеживаются: `wind_max` (мгновенный), `wind_max_1m/10m/1h`, `wind_avr_max_1m/10m/1h`.

## Производные расчёты

| Метрика | Формула | Условия |
|---------|---------|---------|
| Точка росы | Магнус: `γ=ln(RH/100)+17.67T/(243.5+T)`, `dp=243.5γ/(17.67−γ)` | 0 < RH < 100 |
| Ощущаемая темп. | `13.12+0.6215T−11.37v^0.16+0.3965T·v^0.16` (v км/ч) | T < 10 °C, v > 1.39 м/с |
| Тренд давления 30м | `(P_now − P_avg_30min) × 1.33322` → гПа | Скользящее окно 30 образцов |

### Прогноз погоды (эвристика)

| Условие | Вывод |
|---------|-------|
| trend < −3 гПа И RH > 80% | `rain_likely` (вероятен дождь) |
| trend < −2 гПа | `change_expected` (ожидается смена) |
| trend > +3 гПа | `clearing` (прояснение) |
| (T − dp) < 3 °C И T < 15 °C | `fog_possible` (возможна дымка) |
| Ветер > 10 м/с | `strong_wind` (сильный ветер) |
| иначе | `stable` (стабильно) |

### Здоровье датчиков

| Проверка | Порог |
|----------|-------|
| Расхождение температуры (DS18 vs SHT31) | > 3 °C |
| Расхождение влажности (BME vs SHT31) | > 10 % |

Статус: `ok` → `warning` → `offline` (обнаружен NaN).

## Установка

### 1. Arduino мастер

1. Установить библиотеки **EtherCard** (JeeLabs) + **DallasTemperature**
2. Открыть `WX_master   .ino` в Arduino IDE
3. Настроить сеть (DHCP или статический IP)
4. Записать в Arduino Nano

### 2. Python-сервисы

```bash
pip install paho-mqtt

# Запуск сервисов (отдельные терминалы или systemd)
python3 Gen_WX.py
python3 WX_2_MQTT.py
python3 WX_2_WEE.py    # только при использовании WeeWX
```

### 3. WeeWX (опционально)

1. Установить WeeWX 5.2.0
2. Разместить `weewx.conf` в каталоге конфигурации
3. `weewxd -f weewx.conf`

### 4. Тестирование (без аппаратной части)

```bash
# Терминал 1: запустить сервис
python3 WX_2_MQTT   .py

# Терминал 2: эмулятор (60 пакетов, 1 Гц)
python3 WX_emulator.py --dst 127.0.0.1 --count 60

# Полный набор тестов
python3 tests/test_v171.py
python3 tests/test_calculations.py
python3 tests/test_mqtt_integration.py
```
